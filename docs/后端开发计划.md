# 后端开发计划

本文档基于当前数据库设计、API 设计、SOC 和领域模型整理，技术栈采用 Python + FastAPI + MySQL + LangChain。

## 一、总体目标

第一版后端不做复杂任务系统和额外持久化表，围绕核心闭环实现：

1. 用户注册、登录、鉴权。
2. 上传 PDF 简历并抽取字符串文本。
3. 简历解析 Agent 输出标准 Pydantic 对象。
4. 标准简历信息写入 MySQL 的 9 张精简表。
5. 用户查询、校对、保存简历。
6. 用户选择系统预置 LaTeX 模板。
7. 模板 Agent 根据简历信息和模板文件生成 `.tex` 下载链接。
8. 用户提交岗位 URL，系统抓取岗位内容并保存。
9. 岗位分析 Agent 输出匹配度、是否适合、置信来源。
10. 简历优化 Agent 基于已有内容给出优化建议，不虚构经历。
11. 管理员查询、禁用、启用用户账号。

## 二、后端分层

当前脚手架采用以下结构：

| 层级 | 目录 | 职责 |
|---|---|---|
| API 层 | `backend/app/api/v1/endpoints` | 接收请求、鉴权、参数绑定、返回统一响应 |
| Service 层 | `backend/app/services` | 业务流程编排、数据库读写、权限校验 |
| Agent 层 | `backend/app/agents` | 封装 LangChain 调用，输出 Pydantic 标准结果 |
| Crawler 层 | `backend/app/crawlers` | 抓取岗位 URL 页面内容 |
| Model 层 | `backend/app/models` | SQLAlchemy ORM 模型，对应 9 张 MySQL 表 |
| Schema 层 | `backend/app/schemas` | Pydantic 请求、响应、Agent 输出结构 |
| Core 层 | `backend/app/core` | 配置、JWT、安全、异常处理 |
| DB 层 | `backend/app/db` | 数据库连接和 Session 管理 |

数据库层不加外键，所有表关系由业务逻辑保证。

## 三、阶段计划

### 阶段 1：基础环境和数据库

目标：让后端能连接虚拟机 MySQL，并跑通健康检查。

任务：

1. 在虚拟机 MySQL 中执行 `database/init.sql`。
2. 修改 `backend/.env` 中的 `DATABASE_URL`。
3. 安装 `backend/requirements.txt`。
4. 启动 FastAPI：`uvicorn app.main:app --reload --host 0.0.0.0 --port 8080`。
5. 访问 `/health` 和 `/docs`。

验收：

- `/health` 返回成功。
- `/docs` 可以看到 API 文档。
- `GET /api/v1/resume-templates` 在登录后能返回模板列表。

### 阶段 2：用户与权限

目标：完成用户注册、登录、JWT 鉴权和管理员权限。

任务：

1. 实现并测试 `POST /auth/register`。
2. 实现并测试 `POST /auth/login`。
3. 实现并测试 `GET /auth/me`。
4. 手动在数据库把某个用户 `role` 改成 `ADMIN`。
5. 实现管理员查询用户、禁用用户、启用用户。

验收：

- 普通用户只能访问自己的简历。
- 管理员接口只允许 `ADMIN` 访问。
- `DISABLED` 用户不能登录。

### 阶段 3：PDF 简历解析入库

目标：跑通 PDF 上传到简历入库。

任务：

1. 完成 PDF 文件格式、大小校验。
2. 使用 `pypdf` 抽取 PDF 字符串。
3. 完善 `ResumeParseAgent` 提示词。
4. 用 Pydantic 校验 Agent 输出。
5. 将结果写入 `resume`、`education_info`、`project_info`、`intern_info`、`award_info`。
6. 返回解析后的简历预览。

验收：

- 上传 PDF 后生成一条 `resume`。
- 教育、项目、实习、获奖信息能分表写入。
- Agent 不确定的内容不强行编造，允许用户后续校对。

### 阶段 4：简历校对与编辑

目标：让用户可以查看、修改、保存解析后的简历。

任务：

1. 实现简历列表查询。
2. 实现简历详情查询。
3. 实现简历校对保存。
4. 保存时重建明细表，保持第一版逻辑简单。
5. 实现简历软删除。

验收：

- 用户只能查看和修改自己的简历。
- 修改后再次查询能看到最新内容。
- 删除后列表不再展示该简历。

### 阶段 5：LaTeX 模板生成

目标：用户选择系统预置模板后生成 `.tex` 下载链接。

任务：

1. 完善 `resume_template` 初始化数据。
2. 准备真实 LaTeX 模板文件。
3. 完善 `LatexTemplateAgent` 提示词。
4. 读取简历详情和模板文件。
5. 生成 `.tex` 文件并返回下载地址。

验收：

- `GET /resume-templates` 返回模板列表。
- `POST /resumes/{resumeId}/generate-latex` 能生成 `.tex`。
- `GET /resumes/{resumeId}/latex/download` 能下载代码文件。

### 阶段 6：岗位 URL 解析与匹配

目标：把 Boss 直聘等岗位 URL 的内容抓取并用于简历匹配分析。

任务：

1. 完善 `JobCrawler`。
2. 保存岗位 URL、岗位名称、公司名称、岗位正文。
3. 完善 `JobAnalysisAgent` 提示词。
4. 输出匹配度、是否适合、置信来源。
5. 将分析结果保存到 `job.content`。

验收：

- 提交岗位 URL 后生成 `job` 记录。
- 分析结果能说明匹配依据。
- 抓取失败时 `job.status` 为 `FAILED`。

### 阶段 7：简历优化建议

目标：基于已保存简历和可选岗位内容生成优化建议。

任务：

1. 完善 `ResumeOptimizeAgent` 提示词。
2. 分析技能是否足够。
3. 分析个人介绍是否合理。
4. 检查项目、实习经历是否使用 STAR/STAT 表达法则。
5. 明确约束：不能虚构项目、经历、数据和成果。
6. 将建议保存到 `opt`。

验收：

- 不传 `jobId` 时能做简历自身优化。
- 传 `jobId` 时能结合岗位要求分析。
- 优化建议能标记为 `USED`。

## 四、Agent 开发顺序

建议按以下顺序替换 mock：

1. `ResumeParseAgent`：最关键，决定入库结构质量。
2. `LatexTemplateAgent`：保证简历生成闭环。
3. `ResumeOptimizeAgent`：用于展示智能分析能力。
4. `JobAnalysisAgent`：依赖岗位抓取质量，最后完善。

## 五、接口优先级

第一优先级：

1. `POST /api/v1/auth/register`
2. `POST /api/v1/auth/login`
3. `POST /api/v1/resumes/upload-pdf`
4. `GET /api/v1/resumes/{resumeId}`
5. `PUT /api/v1/resumes/{resumeId}`
6. `GET /api/v1/resume-templates`
7. `POST /api/v1/resumes/{resumeId}/generate-latex`

第二优先级：

1. `POST /api/v1/resumes/{resumeId}/jobs/analyze`
2. `POST /api/v1/resumes/{resumeId}/optimize`
3. `GET /api/v1/resumes/{resumeId}/jobs`
4. `GET /api/v1/resumes/{resumeId}/opts`

第三优先级：

1. `GET /api/v1/admin/users`
2. `PATCH /api/v1/admin/users/{userId}/disable`
3. `PATCH /api/v1/admin/users/{userId}/enable`

## 六、测试建议

第一版测试不需要过重，建议覆盖：

1. 注册账号重复校验。
2. 登录成功和失败。
3. 非本人不能访问简历。
4. PDF 解析失败返回错误。
5. 简历保存后明细表数量正确。
6. 模板不存在时生成失败。
7. 优化建议不能访问别人的简历。

## 七、当前注意事项

1. `.env.example` 中的 MySQL 地址只是示例，需要改成你的虚拟机地址。
2. 当前 Agent 默认 `LLM_MOCK=true`，适合先跑通业务流程。
3. 切换真实 LangChain 调用时，设置 `LLM_MOCK=false` 并配置 `OPENAI_API_KEY`。
4. 数据库没有外键，删除和归属校验必须在 Service 层认真处理。
5. `job.content` 和 `opt.content` 第一版用文本或 JSON 字符串保存，避免新增表。
